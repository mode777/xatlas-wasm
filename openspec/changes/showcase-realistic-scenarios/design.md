# Design

## Context

See `proposal.md` for motivation. The current state that shapes this design:

- The `showcase-site` capability is now in the main specs
  (`openspec/specs/showcase-site/spec.md`), after syncing and archiving the
  completed `showcase-site` change.
- `site/src/demos/index.ts` exports six scenarios: `gazebo`, `cube`,
  `uv-sphere`, `terrain`, `packing-lab` and `multi-atlas`. The `cube` and
  `terrain` scenarios are generated by `site/src/demos/geometry.ts`.
- `site/src/gallery.ts` renders a fabricated `.demo-card-visual` with five
  generated chart spans per card and a `.hero-board` chart sheet in the hero;
  `site/src/styles.css` defines those shapes.
- `site/src/demos/types.ts` returns one `DemoInput` per scenario.
  `site/src/worker/run-scenario.ts` adds one mesh, calls `getMesh(0)` and
  flattens it into combined positions/UVs/chart IDs/atlas IDs/indices. The
  viewer, downloads and statistics consume that combined result.
- The only external model today is `gazebo.obj` (MIT, 480 vertices, 730
  faces), embedded as a TypeScript string in
  `site/src/demos/assets/gazebo.ts`.
- XW-025's measured production output is a 173,401-byte wasm artifact
  (69.53 KB gzip), a 573.5 KB lazy demo chunk (142.9 KB gzip) and a 29.0 KB
  lazy code chunk (11.2 KB gzip).

The Cesium Milk Truck source measured for this design is the Khronos glTF
Sample Asset at commit `8f492390ddc7a2ae221a1369ef560589cf8c70fb`:
`CesiumMilkTruck.glb` is 369,980 bytes (SHA-256
`09371b34608116de5842d23abe260bf11acf3e1554daf334a647eb566eee5c49`). Its
three meshes produce five triangle-primitive instances: the wheel mesh is
referenced by two nodes, so the whole truck has 4,823 positions and 10,872
indices (3,624 triangles), plus a body mesh and a root Y-up-to-Z-up rotation.
Textures, materials and the animation are not needed.

## Goals / Non-Goals

**Goals:**

- Replace the two synthetic catalog entries with a production vehicle and a
  composed multi-model town level.
- Prove xatlas packs more than one input mesh into one combined result, without
  changing the site's viewer/download contract.
- Make the gallery's presentation honest: text metadata and live views, no
  fabricated preview artwork.
- Keep every external asset reproducible, attributed and local to the build.

**Non-Goals:**

- Runtime GLB loading, texture sampling, animation playback or a general glTF
  importer in the site.
- Changing `xatlas-wasm`, its loader, `dist/xatlas.wasm` or the published
  package.
- The deferred `showcase-gallery` features (filters, coverage, presets, chart
  highlighting, UV repack), `showcase-docs` and `showcase-thumbnails`.
- A photorealistic or externally licensed game level. The level is intentionally
  composed from the MIT Gazebo, the CC BY 4.0 Milk Truck and generated town
  fabric.

## Decisions

### D1 — Curated six-scenario catalog

Replace `cube` and `terrain` with:

- `milk-truck` — the Cesium Milk Truck, a real hard-surface vehicle with wheels,
  windows and body panels.
- `town-level` — a multi-model town square containing the Gazebo, the Milk
  Truck, generated buildings, roads and props, added as several xatlas meshes.

Keep `gazebo`, `uv-sphere`, `packing-lab` and `multi-atlas` because they cover
architectural geometry, a smooth closed surface, packing stress and
multi-atlas spill respectively. Remove `cube.ts` and `terrain.ts`, remove
`createCube` and `createTerrain` from `geometry.ts`, and make `createDenseGrid`
standalone so the `multi-atlas` scenario does not depend on a terrain example.

Alternatives considered:

- **Keep cube and terrain and grow to eight scenarios.** Rejected: the request
  is to remove them, and a curated six keeps the gallery focused.
- **Replace the Gazebo too.** Rejected: it is already a real MIT asset and
  provides a useful architectural counterpoint to the vehicle and level.

### D2 — Extract the Milk Truck once; embed geometry, not a GLB loader

Add `site/scripts/embed-glb.mjs`, a build-time Node script that:

1. parses the GLB header and JSON/BIN chunks;
2. walks the default scene's node tree and composes each node's world matrix
   from `matrix` or translation/rotation/scale;
3. for every mesh primitive with mode `TRIANGLES`, reads the `POSITION` and
   index accessors (unsigned byte, unsigned short or unsigned int), applying
   the node world transform to positions;
4. concatenates the primitives, validates finite positions and in-range
   indices, and writes `site/src/demos/assets/milk-truck.ts` with
   `Float32Array` positions, `Uint32Array` indices and provenance metadata
   (source URL, pinned commit, license, copyright, vertex/triangle counts and
   source SHA-256).

The committed generated module is imported by `milk-truck.ts` and
`town-level.ts`. The script requires a local GLB path; it does not run during
`npm run build`, so the site build and Node tests never fetch the model. The
generated module is not part of the Code tab: `demos/sources.ts` globs only
`./scenarios/*.ts`.

Plain typed-array literals are chosen over a runtime base64 decoder: the
module is generated, Vite/Node load it directly, and the extra source size
compresses well. If the lazy chunk grows beyond the measured budget, a compact
encoding can be introduced as a separate change.

Alternatives considered:

- **Load the GLB at runtime with three's `GLTFLoader`.** Rejected: unnecessary
  network failure modes, textures/materials/animation work, and the Node test
  suite would need a different loader path.
- **Use a GLB parser in the site bundle.** Rejected: the asset is fixed and
  known; a parser is dead weight at runtime.
- **Use the Cesium repository copy.** Rejected: the Khronos sample asset has
  explicit CC BY 4.0 legal metadata and a stable pinned revision.

### D3 — Scenarios may add multiple meshes; the result stays combined

Extend the pure scenario contract so `build(context)` returns one `DemoInput`
or a readonly array of them. Add `addMeshes(context, inputs)` in
`site/src/demos/mesh.ts`, which calls the checked `context.addMesh` for each
input and returns the inputs in add order. Existing scenarios keep returning a
single input.

`site/src/worker/run-scenario.ts` normalises the return value to an array and:

- asserts the normalized input count matches `atlas.meshCount` after
  `generate`;
- loops `getMesh(i)` for every mesh, allocating combined positions, UVs, chart
  IDs, atlas IDs and indices from the sum of the output counts;
- maps each output vertex's `xref` back to that mesh's input positions and
  offsets each mesh's indices by the combined output vertex base;
- concatenates chart metadata and sums input/output counts; `meshCount` is the
  number of added meshes.

The `ScenarioRun` shape and the viewer/download consumers stay unchanged: they
already read flat arrays and never know how many wasm meshes produced them.
This preserves the worker's ownership rule (the atlas is destroyed in
`finally`; the main thread gets copies) and avoids a second result shape.

Alternatives considered:

- **Merge all level models on the CPU before `addMesh`.** Rejected: it hides
  xatlas's multi-mesh capability and makes `meshCount` always one.
- **Return one result object per mesh to the main thread.** Rejected: the
  viewer, OBJ export, UV view and atlas view would all need multi-result
  handling, and structured cloning would be larger.
- **Keep the single-mesh contract and fake the level with one merged mesh.**
  Rejected: the request explicitly asks for a multi-model scene, and the
  multi-mesh path is the honest demonstration.

### D4 — Compose a town level from real and generated meshes

Add a pure `site/src/demos/town.ts` (no DOM, three.js or Vite-only imports)
that builds a roughly 40 × 40 unit town square as separate meshes:

- ground/plaza and road strips;
- six to eight low-poly buildings with roofs and simple facade bands;
- the Gazebo at the centre;
- the Milk Truck parked on the road;
- props: lamps, benches, planters and crates.

A small `transformMesh`/`composeMeshes` helper applies translation, Y rotation
and positive scale, clones positions and indices, and preserves winding.
Negative scales are not used, so index reversal is unnecessary. The scenario
returns the meshes through `addMeshes`; `meshCount` is therefore greater than
one.

The level uses `packOptions: { createImage: true, resolution: 1024, padding: 2,
bilinear: true }` and a modest `chartOptions.maxCost` so the atlas stays
readable. The exact building count and triangle count are tuned during
implementation; the target is roughly 8,000–15,000 input triangles and a
result that unwraps comfortably within the existing 60-second test timeout.
`getMesh()` still returns one object per output vertex, so the level must not
approach the stress sizes reserved for XW-011.

Alternatives considered:

- **Use a complete external level (for example Sponza or VirtualCity).**
  Rejected: large payloads and restrictive or unclear redistribution terms for
  a public MIT repository.
- **Generate a level with no real assets.** Rejected: it would repeat the
  synthetic-content problem this change is fixing.

### D5 — Remove fabricated preview art, keep live views

In `site/src/gallery.ts`:

- delete the `demo-card-visual` block and its generated chart spans;
- move the ordinal and input badge into the card body so the required metadata
  remains visible;
- delete the hero `hero-board` sheet and its label, leaving a single-column
  hero with the copy and facts.

In `site/src/styles.css`, delete the `.hero-board*`, `.demo-card-visual`,
`.demo-card-grid`, `.demo-card-chart*` and absolute-positioning rules, and
restyle the ordinal/input badge as normal text. The responsive rules for the
hero board go too.

Scenario pages keep the live 3D, UV and Atlas views; those are real results
from the run and are the only previews. `site/test/dom.test.ts` gains an
assertion that the gallery contains no preview art, no `<img>` and no
`<canvas>`.

Alternatives considered:

- **Use captured screenshots as thumbnails.** Rejected: the user explicitly
  asked to remove preview pictures, and real captures are the deferred
  `showcase-thumbnails` follow-up.
- **Keep the hero board only.** Rejected: it is the same fabricated chart
  artwork in a larger form.

### D6 — Provenance, documentation and validation

Update `site/src/demos/assets/NOTICE.md` with the Milk Truck entry: Khronos
glTF Sample Assets URL, pinned commit, CC BY 4.0 license, copyright and the
local extraction script. Note that only geometry is embedded and the Cesium
logo texture is not used.

Update:

- `site/README.md`: new scenario list, multi-mesh scenario contract, Milk Truck
  attribution and regeneration command.
- `README.md`: the live gallery description and scenario count wording.
- `docs/improvements.md`: the XW-025 progress/follow-up entry, recording that
  the realistic-scenario refresh is implemented by this change and that the
  rest of `showcase-gallery` remains deferred. No new XW item is introduced.
- `BUILD.md` only if the site commands change; the existing build/test commands
  stay valid.

Tests:

- `site/test/catalog.test.ts`: the six new stable IDs and metadata.
- `site/test/dom.test.ts`: six text-only cards, no preview art, scenario pages
  still expose four tabs.
- `site/test/geometry.test.ts`: remove cube/terrain tests; add transform and
  town-level tests for finite geometry, valid indices and multiple meshes.
- `site/test/demos.test.ts`: the existing per-scenario validation plus
  `town-level` `meshCount > 1` and combined count checks.
- `site/test/assets.test.ts` (new): Milk Truck vertex/triangle counts,
  finite positions, in-range indices and provenance fields.
- `site/test/sources.test.ts` and `site/test/obj-export.test.ts` continue to
  cover the new scenario sources and downloads.

No workflow, package, loader or API changes are required. The existing site
job in `.github/workflows/build-wasm.yml` already runs typecheck, tests and the
production build for every push/PR.

## Risks / Trade-offs

- **GLB node transforms or winding are applied incorrectly** → The extraction
  script composes world matrices, validates finite positions and index ranges,
  and the visual check plus xatlas's existing winding handling catch errors.
  The generated module records source counts so a regression is visible.
- **Milk Truck licensing or trademark** → Embed geometry only under CC BY 4.0
  with copyright and license text in `NOTICE.md`; do not embed textures or the
  Cesium logo.
- **The town level is too heavy for `getMesh()` object arrays** → Keep it to a
  target triangle budget, use low-poly generated fabric, measure the run and
  reduce building/prop counts if needed. The bulk result API remains XW-011.
- **Multi-mesh flattening drops a mesh or mis-offsets indices** → Assert input
  count equals `meshCount`, test `town-level` combined counts, and validate
  every index in every scenario test.
- **Removing preview art makes the gallery visually plain** → Use clear
  typographic cards and the existing live views; real thumbnails remain a
  future change if wanted.
- **The lazy demo chunk grows** → Measure the production output and gzip size;
  the asset compresses as numeric arrays. If the budget is exceeded, switch the
  generated module to a compact encoding in a follow-up.
- **Removed routes break bookmarks** → This is an intentional site-only
  breaking change; `#/p/cube` and `#/p/terrain` show the not-found page and the
  README documents the new catalog.

## Migration Plan

The `showcase-site` capability has already been synced and archived, so this
change applies as a normal spec delta on `main`.

1. Land the asset extraction script and generated Milk Truck module with the
   provenance notice.
2. Land the multi-mesh contract/worker change and its tests before or together
   with the town-level scenario.
3. Replace the catalog entries and remove the preview art; update the tests and
   docs in the same commit.
4. Roll back by reverting the change: restore the cube/terrain modules and the
   gallery visuals from git. The package, loader and npm publish path are never
   touched.

## Open Questions

- The final town layout, building count and triangle budget can be tuned during
  implementation without changing the specs, as long as the level remains a
  multi-mesh composed scene and stays within the site test timeout.
